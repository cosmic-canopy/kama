# The .kama files the COMPILER rejects with a parse or lexical error — and therefore the exact set the
# tree-sitter grammar must also reject. Repo-relative, one per line, sorted. Checked by
# ../../tools/check-treesitter.sh.
#
# ⚠️ This is NOT "everything under tests/xfail/". Of the 217 other xfail fixtures, every one is a SEMANTIC
# failure that parses perfectly well — a grammar that errored on those would be wrong. The partition is the
# compiler's own parse-vs-semantic split, and it is DERIVED, never hand-curated:
#
#   find tests lib examples prelude -type f -name '*.kama' | sort | while read -r f; do
#       ./kama check "$f" 2>&1 | grep -qE 'Parse error:|Lexical error:' && echo "$f"
#   done
#
# The guard does not re-run that (884 files x ~48 ms is ~43 s). It parses the corpus with tree-sitter in
# one pass, diffs against this list, and only asks the compiler about files where the two DISAGREE — so a
# stale manifest and a wrong grammar are told apart, by name, at no steady-state cost.
#
# ⚠️ An ENCODING refusal (`Encoding error:` — a byte that is not UTF-8 text, KR-91) sits outside that
# partition. The compiler refuses the file before it lexes, while tree-sitter reads decoded text and accepts
# most such files (a stray 0xFF in a string or comment parses fine). So only the ones tree-sitter DOES reject
# are listed — a NUL, and a surrogate encoded in a char literal — and the guard counts an encoding refusal as
# the compiler rejecting when the two disagree. An out-of-range `\u{…}` escape (tests/xfail/lex_escape_*,
# lex_char_escape_*) is outside it too, though the compiler calls it a `Lexical error:`: it is a VALUE check
# — a surrogate, or past U+10FFFF — and a grammar checks an escape's shape, not its number. The derivation
# above lists those files; they do not belong here.
